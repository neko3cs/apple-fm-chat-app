# 要件定義

## 目的・背景

macOS 上で Apple Foundation Models フレームワーク（端末内 LLM）を使ったチャットアプリを作る。
まずは「動く最小限のもの」を目標とし、複数の会話（セッション）の管理や複数モデルへの対応など発展的な機能は範囲外とする。
なお、単一の会話については SwiftData で永続化し、アプリを再起動しても続きから会話できるようにする。

## 想定利用者

- 開発者本人。実機（Apple Silicon Mac、Apple Intelligence 有効済み）で動作確認を行う。

## 機能要件

| # | 機能 | 受け入れ基準 |
| :--- | :--- | :--- |
| 1 | 1 画面のチャット画面 | メッセージ一覧・入力欄・送信ボタンが 1 画面に表示され、送信するとメッセージ一覧に追加される |
| 2 | ストリーミング表示 | モデルの返答が一括表示ではなく、生成されるそばから少しずつ画面に反映される |
| 3 | 同一セッションでの文脈継続 | 同じセッションが使われている間は、前の会話内容を踏まえた返答になる |
| 4 | モデル利用不可時の理由表示 | Apple Intelligence がオフ／準備中／端末非対応のいずれの場合も、画面上にその理由が分かる形で表示される |
| 5 | コンテキスト上限到達時の継続 | 会話が上限（`SystemLanguageModel.contextSize` など、フレームワークが提供する値。決め打ちの数値は使わない）を超えても、操作不能な行き止まりのエラーにはしない。超過を検知した画面に「新しい会話を始める」ことを促す UI を表示し、利用者の操作を経て新しいセッションに切り替えられる |
| 6 | 新しい会話ボタン | ボタン操作で会話をリセットし、新しいセッションを開始できる（永続化済みの会話も破棄される） |
| 7 | 会話の永続化・復元 | 会話（発言・返答）は SwiftData でディスクに保存され、アプリを再起動しても直前までの会話が復元され、続きから会話できる |

## 非機能要件

- 対応環境: macOS 27（Golden Gate）／ Xcode 27 ／ Apple Silicon 搭載 Mac
- 前提条件: Apple Intelligence が有効化済みであること（未確認時は機能要件 4 に従い理由を表示する）
- オンデバイス処理: Private Cloud Compute や他社モデルへの送信は行わない（Foundation Models の端末内モデルのみを使用する）
- 応答性能・可用性の数値目標: TBD（現時点でユーザーから具体的な目標値の指定なし）

## スコープ外

- 複数の会話（セッション）の作成・一覧・切り替え管理（永続化するのは常に単一の会話のみ）
- Private Cloud Compute や他社モデルへの切り替え
- 画像の入力、ツール呼び出し（Tool calling）
- iCloud 同期・他端末との共有（SwiftData はローカル保存のみ）

## 用語集

| 用語 | 意味 |
| :--- | :--- |
| Foundation Models フレームワーク | Apple Intelligence を支える端末内（オンデバイス）大規模言語モデルに Swift からアクセスするための Apple 純正フレームワーク |
| `SystemLanguageModel` | 端末内モデル本体を表すクラス。利用可否（`availability`）や最大コンテキストサイズ（`contextSize`）を取得できる |
| `LanguageModelSession` | モデルとの 1 つの会話文脈（セッション）を表すクラス。同じインスタンスに続けて問い合わせることで文脈を維持する |
| コンテキストウィンドウ／コンテキストサイズ | 1 セッションが保持できるトークン数の上限。超過すると `LanguageModelError.contextSizeExceeded` が送出される |
| ストリーミング応答 | `streamResponse(to:)` により、生成中の内容を逐次受け取る応答方式 |
| `Transcript` | セッション内のやり取り（指示・プロンプト・応答）の履歴を表す構造体。`Codable` に準拠しており、そのままエンコードして保存できる |
| SwiftData | Apple 純正の永続化フレームワーク。`@Model` でアプリのデータモデルを定義し、ローカルディスクに保存する |
