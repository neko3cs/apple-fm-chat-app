# 仕様

## 機能一覧

| # | 機能 | 概要 |
| :--- | :--- | :--- |
| F-1 | チャット画面表示 | メッセージ一覧・入力欄・送信ボタンを 1 画面に表示する |
| F-2 | メッセージ送信 | 入力欄の文字列をモデルへ送り、返答を受け取る |
| F-3 | ストリーミング表示 | 返答を生成途中から逐次更新して表示する |
| F-4 | 文脈の継続 | 同一セッション内で前の会話を踏まえた返答を得る |
| F-5 | 利用可否の表示 | モデルが使えないとき、その理由を画面に表示し入力を抑止する |
| F-6 | コンテキスト上限到達時のプロンプト | 上限超過を検知したら、送信を止めて「新しい会話を始める」ことを促す UI を表示する。継続は F-7 の操作を経て行う |
| F-7 | 新しい会話 | ボタン操作で表示中のメッセージとセッション、および永続化済みの会話を破棄し、新規セッションを開始する。応答生成中に押された場合は、生成中のストリーミングを中断してから新規セッションを開始する |
| F-8 | 会話の永続化・復元 | 送受信のたびに会話を SwiftData へ保存し、アプリ起動時に保存済みの会話があれば読み込んで表示・セッションに反映する |

## 画面仕様

画面は「チャット画面」1 つのみ。画面遷移は発生しない。

| 領域 | 内容 | 振る舞い |
| :--- | :--- | :--- |
| 状態バナー | モデルが利用不可のとき、またはコンテキスト上限に到達したときに表示する理由メッセージ（後述のエラー・メッセージ仕様） | 通常時は非表示。上限到達時は「新しい会話ボタン」を押すまで表示し続ける |
| メッセージ一覧 | 自分の発言とモデルの返答を時系列に並べる | 新しいメッセージが増えたとき、およびストリーミング更新中は最新行が見えるようスクロールする |
| 入力欄 | 送信する本文の入力 | 空文字・空白のみのときは送信できない。応答生成中・モデル利用不可時・コンテキスト上限到達時は入力・送信を受け付けない |
| 送信ボタン | 入力内容を送信する | 上記の送信不可条件では無効表示 |
| 新しい会話ボタン | 会話のリセット（F-7） | 常に押下可能。応答生成中に押された場合は、生成中のストリーミングを中断してからリセットする。コンテキスト上限到達時（F-6）は、この操作が唯一の再開手段になる |

- 応答生成中であることが利用者に分かる表示を行う（進捗インジケータ等）。具体的な見た目は TBD。
- ウィンドウの初期サイズ・最小サイズは TBD。
- 起動直後、保存済みの会話を読み込んでいる間の表示（読み込み中インジケータの要否）は TBD。

## データモデル

画面表示用のメッセージ一覧はアプリ実行中のメモリ上に保持する。会話内容（`Transcript`）自体は SwiftData でローカルディスクに永続化し、アプリ終了後も残る。永続化するのは常に単一の会話のみで、複数の会話を一覧管理する仕組みは持たない。

**メッセージ（画面表示用・メモリ上のみ）**

| 項目 | 型 | 必須 | 説明 |
| :--- | :--- | :--- | :--- |
| id | 一意識別子 | ○ | 一覧表示時の識別に使う |
| 発言者 | 区分（自分 / モデル） | ○ | 表示の左右・配色の切り替えに使う |
| 本文 | 文字列 | ○ | ストリーミング中はモデル側の本文が逐次更新される |
| 生成中フラグ | 真偽値 | ○ | モデルの返答が生成途中かどうか |

**永続化する会話（SwiftData）**

アプリが保持する会話は常に 1 件。`Transcript` が `Codable` に準拠しているため、変換用のフィールドを個別に持たず、エンコードした結果をそのまま保存する。

| 項目 | 型 | 必須 | 説明 |
| :--- | :--- | :--- | :--- |
| id | 一意識別子 | ○ | レコードの識別に使う（常に 1 件のみ存在） |
| transcriptData | バイナリ（Foundation Models の `Transcript` をエンコードしたもの） | ○ | 会話が進むにつれて肥大化しうるため、SQLite 本体とは別領域に保存する |
| updatedAt | 日時 | ○ | 最終更新日時。用途（表示するか等）は TBD |

「新しい会話」操作、および要件のスコープ外である複数会話管理をしないことから、このレコードは常に 0 件または 1 件で、追加のたびに新しい行を増やすのではなく、既存レコードを置き換える（upsert）。

## エラー・メッセージ仕様

利用者に見せる文言は TBD（内容の方向性のみ確定、正確な文面は未確定）。

| 条件 | 画面に伝えるべき内容 |
| :--- | :--- |
| 端末が Apple Intelligence 非対応（`.unavailable(.deviceNotEligible)`） | この Mac では利用できないこと |
| Apple Intelligence が無効（`.unavailable(.appleIntelligenceNotEnabled)`） | 設定で Apple Intelligence を有効にする必要があること |
| モデル準備中（`.unavailable(.modelNotReady)`） | モデルのダウンロード等が進行中で、時間をおくと使えること |
| その他の理由（`.unavailable(_)`） | 原因が特定できず現在利用できないこと |
| 応答生成の失敗（上記以外のエラー） | 返答の取得に失敗したこと。再送信できること |
| コンテキスト上限到達（`LanguageModelError.contextSizeExceeded`） | これ以上この会話を続けられないこと、「新しい会話」を始めれば継続できること。正確な文言は TBD |
| 保存済み会話の読み込み失敗 | TBD。壊れたデータを無視して空の会話から始めるか、エラーとして伝えるか未確定 |

- コンテキスト上限超過時は、超過を引き起こした発言への応答を得ることはできない（フレームワーク側がプロンプト全体を失敗させるため）。自動では継続せず、F-6 のプロンプト表示と F-7（新しい会話）の操作を経て利用者自身が継続する。超過を招いた発言の内容を保持し再入力しやすくするか、単に消えるだけにするかは TBD。
- SwiftData への保存に失敗した場合にエラー表示するかどうかは TBD（会話自体は継続できるため、画面表示は優先度低とする案もある）。
